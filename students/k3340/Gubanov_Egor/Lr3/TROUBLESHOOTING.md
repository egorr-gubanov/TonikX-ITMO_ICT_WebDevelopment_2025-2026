# Устранение проблем с GitHub Pages

## Проблема: 404 Not Found

Если вы видите ошибку 404 при попытке открыть документацию, выполните следующие шаги для диагностики:

## Шаг 1: Проверка GitHub Actions

1. Перейдите в репозиторий на GitHub
2. Откройте вкладку **Actions**
3. Найдите workflow **"Deploy Lr3 MkDocs Documentation"**
4. Проверьте статус последнего запуска:
   - ✅ **Зеленый значок** - workflow выполнен успешно
   - ❌ **Красный значок** - есть ошибки, нажмите на workflow и посмотрите логи
   - 🟡 **Желтый значок** - workflow выполняется

### Если workflow не запустился:
- Проверьте, что вы находитесь в ветке `gubanov-egorr-lr3`
- Убедитесь, что файлы документации были изменены
- Можно запустить вручную: **Actions** → **Deploy Lr3 MkDocs Documentation** → **Run workflow**

## Шаг 2: Проверка настройки GitHub Pages

1. Перейдите в **Settings** → **Pages** вашего репозитория
2. Проверьте настройки:
   - **Source**: должен быть `Deploy from a branch`
   - **Branch**: должен быть `gh-pages`
   - **Folder**: должен быть `/ (root)`
3. Если настройки другие - измените и нажмите **Save**

### Если ветка `gh-pages` не существует:
- Это нормально при первом запуске
- GitHub Actions создаст ветку автоматически после первого успешного деплоя
- Подождите 2-3 минуты после успешного выполнения workflow

## Шаг 3: Проверка структуры в ветке gh-pages

1. Перейдите в репозиторий
2. Переключитесь на ветку `gh-pages` (если она существует)
3. Проверьте наличие папок:
   ```
   Lr3/
   ├── ResidentalConnect/
   ├── Task1/
   └── Task2/
   ```

### Если структуры нет:
- Workflow еще не выполнился или выполнился с ошибкой
- Проверьте логи в **Actions**

## Шаг 4: Проверка URL

Правильные URL для доступа к документации:

- **ResidentalConnect**: 
  ```
  https://egorr-gubanov.github.io/TonikX-ITMO_ICT_WebDevelopment_2025-2026/Lr3/ResidentalConnect/
  ```
  ⚠️ **Важно**: URL должен заканчиваться на `/`

- **Task1**: 
  ```
  https://egorr-gubanov.github.io/TonikX-ITMO_ICT_WebDevelopment_2025-2026/Lr3/Task1/
  ```

- **Task2**: 
  ```
  https://egorr-gubanov.github.io/TonikX-ITMO_ICT_WebDevelopment_2025-2026/Lr3/Task2/
  ```

### Если URL не работает:
- Убедитесь, что URL заканчивается на `/`
- Попробуйте добавить `index.html` в конце:
  ```
  https://egorr-gubanov.github.io/TonikX-ITMO_ICT_WebDevelopment_2025-2026/Lr3/ResidentalConnect/index.html
  ```

## Шаг 5: Проверка логов GitHub Actions

Если workflow выполнился с ошибкой:

1. Откройте **Actions** → выберите неудачный workflow
2. Нажмите на job **deploy**
3. Разверните шаги и найдите ошибку
4. Частые ошибки:
   - **"Module not found"** - проблема с зависимостями
   - **"Permission denied"** - проблема с правами доступа
   - **"Path not found"** - неправильный путь к файлам

## Шаг 6: Ручной запуск workflow

Если автоматический запуск не сработал:

1. Перейдите в **Actions**
2. Выберите **Deploy Lr3 MkDocs Documentation**
3. Нажмите **Run workflow**
4. Выберите ветку `gubanov-egorr-lr3`
5. Нажмите **Run workflow**

## Шаг 7: Проверка локальной сборки

Чтобы убедиться, что документация собирается правильно:

```bash
cd Lr3/ResidentalConnect
pip install -r requirements.txt
mkdocs build
ls -la site/
```

Если сборка прошла успешно, папка `site/` должна содержать HTML файлы.

## Частые проблемы и решения

### Проблема: "404 Not Found" сразу после пуша
**Решение**: Подождите 2-3 минуты. GitHub Pages обновляется не мгновенно.

### Проблема: Workflow не запускается
**Решение**: 
- Проверьте, что вы в правильной ветке
- Убедитесь, что файлы документации были изменены
- Запустите workflow вручную

### Проблема: Workflow падает с ошибкой
**Решение**:
- Проверьте логи в Actions
- Убедитесь, что все зависимости указаны в requirements.txt
- Проверьте синтаксис mkdocs.yml

### Проблема: Документация не обновляется
**Решение**:
- GitHub Pages может кэшировать страницы
- Попробуйте очистить кэш браузера (Ctrl+Shift+R или Cmd+Shift+R)
- Подождите 5-10 минут

## Проверка статуса деплоя

Выполните следующие команды для проверки:

```bash
# Проверить последние коммиты
git log --oneline -5

# Проверить статус ветки
git status

# Проверить удаленные ветки
git branch -r
```
